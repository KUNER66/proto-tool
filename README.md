# proto-tool

**给任意 HTML 原型贴便利贴，备注直接烧进文件。**

发给别人，双击就能看到。不装工具、不联网、不用账号。

## 这是什么

你画完 HTML 原型，想在上面写几句说明——

「这里文案待定」「这个交互跟需求书不一致」「折返时间要跟乘务组复核」……

Axure 有批注、Figma 有评论，但**一旦导出成 HTML，这些批注就没了**。
在线批注工具（如 Hypothes.is）又要联网、要账号、依附在服务器上，
文件发给别人就看不见了。

**proto-tool 换了个思路：把备注写进 HTML 文件本身。**

```
┌──────────────┐     ┌──────────────────────┐     ┌──────────────┐
│  打开任意     │     │  像贴便利贴一样       │     │  备注烧进     │
│  HTML 原型    │ ──▶ │  在页面上写批注       │ ──▶ │  HTML 文件    │
└──────────────┘     └──────────────────────┘     └──────────────┘
                                                          │
                                                          ▼
                                        发给同事 → 双击 → 备注就在那儿
```

接收方**什么都不用做**：双击文件，便利贴就在原位上，一条不漏。

## 快速开始

### 方式一：直接双击（推荐给非开发者）

1. 装 [Node.js](https://nodejs.org) 18 或更高版本（只需一次）
2. 下载本项目，双击 **`start.bat`**（Windows）或运行 **`./start.sh`**（macOS / Linux）
3. 浏览器自动打开工具界面 → 点「打开原型」→ 选你的 HTML 文件
4. 点 **`+ 备注`** → 在页面上点一下 → 打字。改完自动保存

### 方式二：命令行

```bash
git clone https://github.com/KUNER66/proto-tool.git
cd proto-tool
npm start                  # 启动并自动打开浏览器
```

命令行参数：

| 参数 | 说明 |
|---|---|
| `-p, --port <端口>` | 监听端口（默认 `7317`，也可用环境变量 `PORT`） |
| `-o, --open` | 启动后自动打开浏览器 |
| `-h, --help` | 显示帮助 |
| `-v, --version` | 显示版本号 |

```bash
proto-tool --open                    # 装成全局命令后
node src/server.js --port 7320       # 不装全局，直接传参
PORT=7320 npm start                  # 用环境变量（macOS / Linux）
set PORT=7320 && start.bat           # 用环境变量（Windows）
```

### 方式三：只想看看效果

`examples/` 里有两份测试原型，直接用工具打开即可。

## 怎么用

| 操作 | 说明 |
|---|---|
| **`+ 备注`** | 进入贴纸模式，点页面任意位置放置便利贴 |
| **拖便利贴** | 按住拖动换位置，自动重新锚定到当前位置的元素 |
| **点文字** | 直接编辑内容；清空原有内容 = 删除 |
| **类型下拉** | 切换「正式说明」（黄）/「内部待办」（紫） |
| **`内部待办`** | 临时展开/折叠待办。**编辑时默认折叠，发给别人时全部显示** |
| **`清单`** | 集中查看、定位、改类型、标完成、删除 |
| **`导出文本`** | 把全部备注复制成纯文本，方便贴进需求文档或会议纪要 |

工具条（宿主页）：`打开原型`（Ctrl+O）· `重新载入` · `清除备注`

## 两类备注

| 类型 | 颜色 | 用途 |
|---|---|---|
| **正式说明** | 黄 | 给评审人看的正式批注 |
| **内部待办** | 紫 | 自己内部的待办事项 |

编辑时待办默认折叠（页面清爽），**分发给别人时两类都会显示，一条不漏**。

## 核心特性

### 备注烧进文件，不是存在别处

备注数据和渲染代码都写进目标 HTML，用注释标记包住：

```html
<!-- AN:NOTES:BEGIN --><script id="an-data" type="application/json">{...}</script><!-- AN:NOTES:END -->
<!-- AN:RUNTIME:BEGIN --><script id="an-runtime">...</script><!-- AN:RUNTIME:END -->
```

接收方双击文件，运行时自动读取数据块并渲染便利贴。**零网络请求。**

### 反复保存不会把文件撑大

采用**幂等注入**：每次保存先按 id 定位并剥离上次注入的整块，再插入新的。
保存一百次，文件里也只有一份数据、一份运行时代码，体积稳定。

> 这条有单元测试守着：`test/injector.test.js` 里断言「注入 N 次后剥离，结果与原文逐字节一致」。

### 备注会跟着页面元素走

便利贴不是死钉在屏幕坐标上——它记住自己盖在**哪个元素**上，以及相对偏移。
页面切换标签页、元素显隐、窗口缩放时，备注会跟着重算位置；
锚点消失时自动隐藏，回来时自动复原。

### 编辑权限不会泄露给接收方

工具通过 iframe 打开原型时，会临时注入一行编辑凭证让运行时进入可编辑状态。
**这行凭证只在渲染给工具自己看的那份 HTML 里，落盘时被排除。**

所以：你拿到的文件可编辑，发给别人的同一份文件是**只读展示**。
接收方看到右下角一个「备注 N」小浮标，点开看清单，不会误改你的文件。

> 这条也有测试守着：断言磁盘文件里不存在 `window.__AN_EDIT__ = {...}` 赋值语句。

## 项目结构

```
proto-tool/
├── start.bat                   Windows 启动器（双击即用）
├── start.sh                    macOS / Linux 启动器
├── package.json
├── lib/
│   └── injector.js             ★ 注入核心：剥离 / 构造 / 读写（纯字符串，无依赖）
├── src/
│   ├── server.js               本地服务：静态资源 + 文件浏览 + 写盘
│   ├── index.html              工具宿主界面
│   └── runtime/
│       └── annotator.js        ★ 注入到目标 HTML 的运行时
├── test/
│   ├── injector.test.js        注入逻辑单元测试
│   └── server.e2e.js           本地服务端到端测试
├── examples/                   示例原型
└── docs/                       文档与截图
```

`lib/injector.js` 是**纯函数模块**——不依赖 `fs`、`http` 或任何环境，
所以本地服务、未来的桌面端、CLI、单元测试可以共用同一套注入语义，
不会出现「两边实现各改各的」导致行为漂移。

## 为什么需要本地服务

浏览器的安全策略不允许网页直接改写磁盘文件。
所以需要一个本地小程序在中间转发：

```
工具界面（浏览器）  ──HTTP──▶  本地服务（Node）  ──写盘──▶  你的 HTML 文件
```

服务只监听 `127.0.0.1`，不对外暴露，**数据不出本机**。

### 为什么用页面内的文件浏览器，不用系统弹窗

最初试过调系统原生「打开文件」对话框，有两个绕不过的坑：

1. 那个对话框是独立进程，**抢不到浏览器前台焦点**，会跑到别的窗口去，用户以为没反应
2. GUI 程序的输出**不走命令行管道**，Node 读回来永远是空 → 前端拿不到选择结果

改成页面内自绘的文件浏览器后，窗口始终在当前页，路径与选择结果都走 HTTP 传递，
两个问题一起消失。

## 已知限制

- **只支持单文件 HTML。** 如果你的原型是 HTML + 外部 CSS/JS 的多文件结构，
  注入仍然生效，但分发时需要把资源目录一起带上。
- **会改写原文件。** 工具直接把备注写进你选的那个 HTML。建议对重要原型先做版本管理（Git）。
  工具内置「清除备注」，可一键还原成干净原型。
- **不做协同编辑。** 适合「我写批注给你看」的单向场景，不是实时协作工具。
